# V-JEPA actual checkpoint qualification: CPU only

Inspected `nurikw3/rsna-knee-vjepa21-checkpoints/f0_best.pt` rather than relying on its model title. Retained original under `.audit/vjepa21-checkpoint-audit/`; no publisher code imported or executed, no GPU, no study inference or training, no CSV/submission. `audit_checkpoint.py` uses only `torch.load(..., map_location='cpu', weights_only=True)` with no unsafe retry or added safe globals. Three unit tests cover finite state, malformed/nonfinite rejection and non-export of study identifiers.

The 363,835,140-byte file SHA-256 is `6cc9612676a655ef7f5bb94ae0c57fc7e487b46a2390c255870495a570f73b2f`. All197 tensors are finite float32: 90,939,306 elements, encoder158 entries, head37, plus two pixel normalization buffers. Shape identity and metadata inventory are retained in `vjepa_checkpoint_receipt.json`. This is not strict reconstruction or output parity.

Unlike the initial source-only audit, the checkpoint contains a `contract`, epoch7 and a score dictionary. The contract records fold0, eight configured epochs, BF16/FP32 weights, RTX5090 hardware, seed42, train.csv hash matching our official metadata, target-file hash `eb4c2b29e7e84adbb4b5ccee825ca20ade6a43dbe295f13be442d549e4f5dca4`, and policy `gold_holdout_v4_soft_margin_weight_v1`. Its `finetune_model.py` hash matches the previously audited downloaded source. It names hashes for IDs, reference folds, input NPZs, initializer and other training sources, but the corresponding bytes and exclusion maps are not established by these assertions.

Stored macro score is **0.776107671322023** across12 targets. The checkpoint does not identify the evaluated population sufficiently to label this gold, true OOF, independent pathology evidence or public leaderboard AUC. Do not equate it to our0.957, claim it failed a paired test, or infer that all five folds score similarly. It supplies no positive evidence justifying last-day GPU expenditure. Published preprocessing still contains the separately documented double-DICOM-read and zero-view fallback paths. Do not run them against hidden data.

Next qualification would require the actual hashed target/split/source assets, independent evidence and reader repair/parity, not merely downloading the remaining four checkpoints. No such GPU launch follows from this audit. The approved final picks remain unchanged; the separate exact Helios exploratory submission still awaits user approval.
